# Scanning

`depvault scan` checks a repository in one interactive pass: vulnerable dependencies, secrets hardcoded in source, and secret files that aren't in DepVault yet. It reports only — it never uploads files.

```bash
depvault scan [--path <dir>] [--project <id>]
```

| Flag        | Description                                    | Default                   |
| ----------- | ---------------------------------------------- | ------------------------- |
| `--path`    | Repository root.                               | Current repo              |
| `--project` | Project ID.                                    | From `.depvault.json`     |

Requires an interactive terminal. In CI, use `depvault analyze` and `depvault status` instead. If the folder isn't linked yet, `scan` offers [`depvault init`](/cli/sync#link-a-repo-depvault-init) first.

---

## Steps

1. **Dependency analysis** — finds dependency files (`package.json`, `requirements.txt`, `*.csproj`, …), lets you pick which to analyze, and shows vulnerabilities and health scores. See [Dependency Analysis](/guides/dependency-analysis).
2. **Secret leak detection** — scans source files locally for hardcoded secrets (cloud keys, private keys, API tokens, connection strings) and can add the offending files to `.gitignore`.
3. **Secret files** — lists git-ignored secret files that aren't in DepVault yet. Store them with `depvault push`, or skip one for good with `depvault untrack <path>`.
4. **Summary** — counts for each step and a link to the project in the dashboard.
